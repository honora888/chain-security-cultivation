# Quest 1 UI Polish Specification

> 「玄水护阵」视觉增强实施规格。本文件基于当前已上线的 Quest 1 功能、状态机、组件、CSS 和仓库内参考图制定；它描述后续工作，不代表视觉增强已经完成。

## 当前完成度判断

### 结论

Quest 1 的功能闭环已经完成，视觉完成度仍处于“可用 MVP + 明确占位”阶段。

- 已完成：入口页、六幕状态机、Boss HP、代码定位、分类判断、五步攻击回放、CEI 重排与封印、奖励、本地异兽志、Monad Testnet 只读核验、持久化、Reduced Motion 和主要响应式规则；
- 已有视觉基础：宣纸白/云海青灰/玉白、水色强调、深色代码区、朱砂危险色、克制金色、统一按钮与状态反馈；
- 未完成：正式妖兽、徽记、灵珠、卷轴、秘境背景和主要战斗状态美术；当前 `TemporaryVisualPlaceholder` 仍是主要视觉；
- 动画现状：已有 CSS 入场、受击、阵法、资金路径、封印和奖励动画，但多为容器级淡入、位移、描线；尚未建立一致的妖兽动作和视觉叙事；
- 不应改动：真实合约事实、六幕功能边界、本地奖励与链上状态的区分、只读链上查询边界。

### 审查证据与限制

本次审查使用：

1. 当前仓库的 React 组件、reducer、持久化逻辑和 CSS；
2. `web/public/assets/quest-1/reference/` 中八张已跟踪参考图；
3. 当前本地入口页截图核查。

入口页截图确认了现有信息层级和占位状态。当前截图环境中的 `/quests/1` 持续停留在“水灵秘境正在显现”的客户端加载画面，因此没有把该画面作为 ACT1—ACT6 的视觉证据，也不对生产环境可视状态作截图层面的完整审计。六幕审查属于“代码、状态与设计参考的实施审查”，后续每个 Batch 仍需真实浏览器视觉回归。

## 总体视觉方向

### 主题

「玄水护阵」以深水、回环、吞噬、递归、墨色卷宗和水系封印为核心。它应当是“东方修仙 Boss 战中的代码证据学习”，而不是黑色安全仪表盘，也不是高饱和手游战斗。

### 视觉层级

1. 第一层：当前教学证据——代码、资金、调用栈、余额、Diff；
2. 第二层：当前 Boss 状态——姿态、弱点、HP、封印程度；
3. 第三层：世界观——深水舞台、墨色卷宗、水纹与阵法；
4. 第四层：可选证据——卷宗、异兽志、链上核验。

妖兽负责“记住为什么危险”，证据负责“理解哪里危险”。任何美术都不得遮挡第二步操作或第一层证据。

### 画面密度

- 每幕首屏继续遵循一句对白、一个目标、一个主要操作、一句提示；
- 单个阶段最多一个主舞台和一个主证据区；
- 参考图中的角色头像、旗幡、复杂山门、多个徽章仅选一到两项使用；
- 避免在同屏同时出现完整妖兽、完整代码、完整资金表、完整调用栈和长篇说明。

## 页面布局

### 桌面端（≥ 1024 px）

- 顶部 HUD 高度目标 88–104px：返回、幕次/Boss、HP、动态偏好和重置；
- 中央舞台最大宽度 1440px，按阶段选择 55/45 或 60/40 双区，不使用常驻三栏；
- ACT1：妖兽舞台占中央 60–70%，目标区位于底部；
- ACT2/3：代码或判断区为主，妖兽为辅，比例约 62/38；
- ACT4：资金舞台与证据区约 58/42；步骤条横向；
- ACT5：排序或 Diff 为主，封印舞台为辅；完成后可上下布局；
- ACT6：奖励主体居中，链上核验作为后续独立段落；
- 命令栏保持文档流；仅移动端固定。

### 平板（768–1023 px）

- 维持单列，不在 768px 过早进入双栏；
- 证据区在前，妖兽/阵法在后；阶段内 `min-width: 0`；
- 代码与 Diff 只允许内部横向滚动；
- ACT4 调用链切为纵向，余额可保持两列或三列，按实际文字长度测试；
- 主内容底部留出操作栏和安全区空间。

### 移动端（≤ 767 px）

- Boss 舞台高度目标 240–300px；不使用固定像素高度截断角色；
- 主流程为“幕次/HP → 当前证据 → 反馈 → 主操作”；
- 命令栏固定底部，`padding-bottom` 大于栏高并加 `env(safe-area-inset-bottom)`；
- 代码、调用栈、Diff 内部滚动，页面根节点无横向溢出；
- ACT4 路径纵向；ACT5 三印纵向；ACT6 奖励、异兽志、链上核验分段；
- “重置修炼”保持 44px 以上触控区，不重复渲染两个可聚焦按钮；
- 390×844 作为主要美术裁切基线，360×800 作为最窄回归尺寸。

## 响应式设计

### 验收尺寸

- 360×800；
- 390×844；
- 768×1024；
- 1024×768；
- 1440×1024。

### 共通规则

- `document.documentElement.scrollWidth > clientWidth` 必须为 `false`；
- 所有 Grid/Flex 子项设置必要的 `min-width: 0`；
- 代码、调用栈、Diff 是唯一允许局部横向/纵向滚动的区域；
- 长地址与 `reportHash` 使用 `overflow-wrap:anywhere` 或局部 `word-break`；
- 不用 `overflow-x:hidden` 掩盖结构错误；
- 触控目标至少约 44×44px；
- Fixed 命令栏考虑安全区并预留内容底部 padding；
- 图片使用对象定位而非硬裁切角色识别特征。

### 美术裁切

- 桌面主图保留完整断环与 Vault；
- 移动端优先使用 4:5 重构资产，不直接裁 16:9 中央；
- 头像、弱点与状态玉扣不得落在安全区外；
- 背景可裁，妖兽主体不可裁掉断环缺口；
- 移动端非当前步骤的妖兽可缩为状态头像，避免重复大图。

## 无障碍

### 键盘与焦点

- 所有操作继续使用原生 button/input/select；
- `focus-visible` 保持至少 3px 轮廓，深色舞台上使用浅青焦点环；
- CodeLine 的方向键、Home/End 行为保持；
- radio 使用原生方向键行为，Tab 顺序等于视觉顺序；
- CEI 排序后的焦点保留在被移动代码块的对应控制；
- 异兽志打开后应把焦点放入对话框，关闭后返回触发按钮，并实现焦点约束；现有实现需在后续 Batch 补验。

### 图片与装饰

- 妖兽主图 alt 示例：“噬灵回环兽盘踞成断环，胸腹状态节点尚未清零”；
- 同一屏已有完整文字状态时，重复性的妖兽效果层使用空 alt；
- 背景、水雾、水纹、粒子和阵线使用 `aria-hidden`；
- 资金 SVG 仍需相邻文本表格，不能让路径成为唯一信息；
- 徽记 alt 必须写“本地奖励展示”，除非链上查询真实返回相应状态。

### 动态播报

- Boss HP 使用 progressbar，并在稳定变化后播报一次；
- 余额变化将当前步骤、Vault、Attacker、账面余额组合成一次 `aria-live=polite` 文本；
- 不逐帧播报粒子、阵印亮度或动画百分比；
- 错误、部分正确、正确必须包含标题；
- RPC 状态和本地奖励使用不同 live region，避免互相覆盖；
- Reduced Motion 切换只播报一次，完成路径与完整动态等价。

### 对比与非颜色信息

- 普通文本目标 WCAG AA 4.5:1，18pt/粗体大字与 UI 图形至少 3:1；
- Success、Warning、Danger、Info 都有文字标签和边框/形状；
- Disabled 不只降低透明度，还保留清晰文字和 `disabled` 语义；
- 深色代码区的行号、注释和未选代码需要逐色测试；
- 动画可跳过或快速完成，任何学习信息不能只在动画中出现。

## 性能要求

- 先产静态 WebP/AVIF，再评估有限序列；不以复杂 3D 或大型动画依赖为前提；
- 首屏只加载背景、待机主图和必要字体；ACT2–ACT6 资产按需加载；
- 当前参考 PNG 约 1.8–3.1 MB，仅作参考，不作为页面资源；
- `next/image` 固定尺寸和 `sizes`，避免 CLS；
- 不在 React render 中生成大型粒子数组；
- CSS 动画只改变 `transform`、`opacity` 或可控的 SVG stroke，谨慎使用大面积 filter/blur；
- 页面失焦、组件卸载和幕次切换时清理 Timer、音效和动画帧；
- 图片失败显示静态占位、名称和当前状态，不阻断状态机；
- 用生产构建检查路由、LCP、CLS、长任务和内存；ACT4/ACT5 是重点。

## 验收标准

### 角色与视觉

- 噬灵回环兽在 ACT1—ACT6、头像和徽记中身份连续；
- 不再以 Temporary Visual Placeholder 作为主视觉；
- 妖兽不遮挡代码、资金、余额、调用栈、Diff、反馈和主操作；
- 深色只用于舞台、代码和局部卷宗，页面不成为黑色科技仪表盘；
- 金色、冷紫、暗红和辉光均为小面积状态色。

### 教学与状态

- 六幕顺序和现有 reducer 规则不变；
- HP 100 → 75 → 50 → 50 → 0，不因重播、刷新或动画重复扣减；
- ACT4 五步数据与仓库事实一致，并明确“本地教学模拟”；
- EXP 120、水熟练度 +1、Boss HP、异兽志和本地徽记均明确是本地数据；
- Monad Testnet 核验只读，结果不改变本地结算。

### 交互与恢复

- 动画失败、图片失败、刷新和 Reduced Motion 均可到达相同稳定 checkpoint；
- 所有 Timer 有 cleanup，不创建并发播放；
- 主要操作在手机端可见，重置始终可访问；
- 错误、部分正确、正确和未完成都保留明文反馈；
- 异兽志和链上核验关闭/失败后不破坏 ACT6_COMPLETE。

### 响应式与无障碍

- 360×800、390×844、768×1024、1024×768、1440×1024 无页面横向溢出；
- 代码和 Diff 只在内部滚动；
- 触控目标至少约 44px；
- 键盘可完成所有阶段；焦点顺序与视觉顺序一致；
- 状态不只靠颜色；图像 alt、装饰隐藏、live region 和 Boss HP/余额播报正确；
- Reduced Motion 无持续漂浮、缩放、震屏、视差和长动画，信息完全等价。

### 性能

- 不接入多兆字节参考 PNG；
- 首屏关键图固定尺寸，避免明显 CLS；
- 非首屏状态图延迟加载；
- ACT4/ACT5 不产生长任务、无限动画或泄漏 Timer；
- 生产构建和 Vercel 路由保持正常。
